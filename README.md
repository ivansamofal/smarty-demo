# Smarty Demo Blog

Простой блог с категориями и статьями на чистом PHP 8.1+, Smarty и MySQL, без фреймворков.

## Стек

- PHP 8.1+, PDO
- Smarty (шаблонизатор)
- MySQL 8
- SCSS, компилируется чистым PHP через `scssphp/scssphp` (без Node/npm)
- Docker Compose: nginx + php-fpm + mysql

## Быстрый старт (Docker)

```
cp .env.example .env
docker compose up -d --build
docker compose exec app php bin/migrate.php
docker compose exec app php bin/seed.php --count=30
```

Открыть http://localhost:8080. Повторный сидинг с очисткой таблиц: `php bin/seed.php --fresh --count=30`.

## Без Docker

```
composer install
cp .env.example .env   # указать параметры локального MySQL
php bin/migrate.php
php bin/seed.php
php -S 127.0.0.1:8000 -t public public/router.php
```

Открыть http://127.0.0.1:8000.

## Сборка стилей

Исходники SCSS лежат в `scss/`, скомпилированный CSS уже закоммичен в `public/css/app.css`.
Пересобрать после правок:

```
php bin/build-assets.php
```

## Структура проекта

```
public/            точка входа (index.php), статика, скомпилированный CSS
src/
  Config/          загрузка конфигурации из окружения / .env
  Database/        PDO-подключение, миграции, сидинг
  Entity/          неизменяемые сущности Category, Post
  Repository/       SQL-запросы поверх PDO
  Service/          бизнес-логика поверх репозиториев
  Http/            Request, Response, Router
  Controller/       тонкие контроллеры (Home, Category, Post)
  View/            фабрика Smarty
  Support/          value-объекты (пагинация, сортировка, DTO страниц), Slugger
  Exception/        доменные исключения
templates/          Smarty-шаблоны
scss/               исходники стилей
database/schema.sql  схема БД
bin/                 CLI-скрипты: migrate.php, seed.php, build-assets.php
docker/              Dockerfile и конфиги nginx/php-fpm
```

## Архитектура

Front controller (`public/index.php`) собирает зависимости и передаёт запрос в `Router`.
Контроллеры обращаются только к сервисам (`App\Service\*`), сервисы — к репозиториям
(`App\Repository\*`), репозитории инкапсулируют весь SQL поверх `PDO`. Отсутствие
категории/статьи по slug, отсутствие маршрута и ошибки БД выражены собственными
исключениями и превращаются в 404/500 на уровне front controller, без утечки трейсов.

## Использование ИИ

Проект реализован с помощью Claude Code (Anthropic) в режиме пошагового пилотирования:
весь код писала модель, а я выступал в роли архитектора и ревьюера. Конкретно:

- Я разбил задачу на фазы (структура проекта → слой БД → репозитории/сервисы → роутинг
  и контроллеры → сидинг → стили → финализация) и после каждой фазы явно указывал модели,
  что делать дальше.
- Ключевые решения принимал я: структура git-репозитория, единый источник переменных
  окружения для docker-compose и приложения, выбор scssphp вместо Node для сборки SCSS,
  какие несоответствия в первоначальном плане фаз нужно скорректировать по ходу работы.
- Модель писала весь код (PHP-классы, SQL-схему, Smarty-шаблоны, Docker-конфигурацию,
  SCSS), сама проверяла его в поднятом Docker-окружении (миграции, сидинг, HTTP-запросы
  к каждому маршруту) и готовила коммит-сообщения; коммиты в git делал я сам после
  проверки диффа на каждом этапе.
- Каждый этап проверялся вручную: я читал изменения перед коммитом и по ходу работы
  указывал на несостыковки (например, что часть исходно запланированных фаз уже была
  закрыта раньше срока и нумерацию нужно скорректировать).
