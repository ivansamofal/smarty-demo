# Smarty Demo Blog

Блог с категориями и статьями на чистом PHP 8.1+, Smarty и MySQL, без фреймворков.

## Функционал

- Главная страница: каждая категория, в которой есть хотя бы одна статья, со своими
  3 последними по дате публикации статьями и кнопкой "Все статьи". Категории без статей
  на главную не попадают.
- Страница категории: название, описание, список статей с сортировкой по дате публикации
  или по числу просмотров и постраничной навигацией.
- Страница статьи: изображение, название, описание, текст, категории, число просмотров
  (инкрементируется при каждом открытии) и блок из 3 похожих статей.
- Статья может принадлежать одной или нескольким категориям.
- CLI-сидинг категорий и статей со случайными, но осмысленными данными на русском языке.

## Стек

- PHP 8.1+, PDO
- Smarty (шаблонизатор)
- MySQL 8
- SCSS, компилируется чистым PHP через `scssphp/scssphp` (без Node/npm)
- Docker Compose: nginx + php-fpm + mysql
- PHPUnit (юнит- и интеграционные тесты)

## Быстрый старт (Docker)

```
cp .env.example .env
docker compose up -d --build
docker compose exec app php bin/migrate.php
docker compose exec app php bin/seed.php --count=30
```

Открыть http://localhost:8080. Повторный сидинг с очисткой таблиц: `php bin/seed.php --fresh --count=30`.

## Без Docker

```
composer install
cp .env.example .env   # указать параметры локального MySQL
php bin/migrate.php
php bin/seed.php
php -S 127.0.0.1:8000 -t public public/router.php
```

Открыть http://127.0.0.1:8000.

## Сборка стилей

Исходники SCSS лежат в `scss/`, скомпилированный CSS уже закоммичен в `public/css/app.css`.
Пересобрать после правок:

```
php bin/build-assets.php
```

## Тесты

```
docker compose exec app composer test            # unit + integration
docker compose exec app composer test:unit       # без БД
docker compose exec app composer test:integration
```

Юнит-тесты (`tests/Unit`) не трогают БД. Интеграционные (`tests/Integration`) работают с
отдельной базой `smarty_demo_test` (создаётся и настраивается автоматически через
`tests/bootstrap.php` с использованием root-доступа из `.env`) и очищают её перед каждым
тестом — рабочая база (`smarty_demo` из `.env`) не затрагивается.

## Доменная модель

Две сущности и связь многие-ко-многим между ними:

- **Category** — `id`, `name`, `slug` (уникальный, для URL), `description`.
- **Post** — `id`, `title`, `slug` (уникальный), `description` (краткое описание для
  карточек и превью), `content` (полный текст), `image` (путь/URL), `views` (счётчик
  просмотров), `published_at` (дата публикации, по ней и по `views` строится сортировка).
- **post_category** — pivot-таблица (`post_id`, `category_id`), `ON DELETE CASCADE` в обе
  стороны: у статьи может быть 1..N категорий, категория может быть общей у нескольких
  статей.

В коде сущности отражены как неизменяемые (`readonly`) value-объекты `App\Entity\Category`
и `App\Entity\Post` — репозитории всегда возвращают готовые объекты, а не сырые массивы
из PDO. У `Post` есть метод `withViews()`, возвращающий новый экземпляр с обновлённым
счётчиком, — это позволяет показать актуальное число просмотров сразу после инкремента,
не делая лишний `SELECT`.

## Архитектура

Запрос проходит через слои линейно и в одну сторону:

```
public/index.php → Router → Controller → Service → Repository → PDO
```

- **Router** (`App\Http\Router`) — регистрация GET-маршрутов с параметрами вида
  `{slug}`, компиляция шаблона в regex, извлечение именованных groups в массив
  параметров при диспетчеризации. Всего три маршрута: `/`, `/category/{slug}`,
  `/post/{slug}`.
- **Controller** (`App\Controller\*`) — тонкий слой: разбирает query-параметры запроса
  (`sort`, `page`), вызывает ровно один метод сервиса и рендерит Smarty-шаблон. Никакого
  SQL и бизнес-правил в контроллерах нет.
- **Service** (`App\Service\*`) — вся бизнес-логика: `CategoryService` собирает превью
  для главной страницы и постранично отдаёт статьи категории; `PostService` находит
  статью, инкрементирует просмотры и подбирает похожие статьи. Сервисы оперируют только
  сущностями и DTO — про PDO/SQL не знают.
- **Repository** (`App\Repository\*`) — единственное место, где есть SQL. Каждый метод
  решает одну конкретную выборку (последние N статей категории, пагинированный список,
  похожие статьи и т.д.) и возвращает готовые сущности.
- **Support** (`App\Support\*`) — вспомогательные value-объекты, не привязанные к
  конкретному запросу: `PostSort` (backed enum `date`/`views`, знает своё имя колонки),
  `PaginatedResult` (список + метаданные пагинации), `CategoryPreview`/`CategoryPage`/
  `PostPage` — DTO, которые сервисы отдают контроллерам для рендера, и `Slugger` —
  самостоятельная транслитерация кириллицы в URL-slug.
- **Config** (`App\Config\Config`) — единая точка чтения настроек: сперва берёт реальные
  переменные окружения (важно для Docker/php-fpm), затем опционально дополняет их из
  `.env`, если файл существует и переменной ещё нет.
- **Обработка ошибок** — отсутствие категории/статьи по slug и отсутствие подходящего
  маршрута выражены отдельными исключениями (`CategoryNotFoundException`,
  `PostNotFoundException`, `RouteNotFoundException`) и перехватываются один раз, в
  front controller, превращаясь в страницу 404; любое другое исключение — в 500, без
  утечки трейса пользователю.

## Бизнес-логика

- **Главная страница**: `CategoryService::getHomePagePreviews()` берёт только категории,
  у которых есть хотя бы одна статья (`INNER JOIN` с `post_category`, без категорий без
  статей), и для каждой отдельным запросом подтягивает 3 последние по `published_at`
  статьи. N+1 запросов здесь осознанный выбор ради простоты и читаемости — категорий
  на реальном блоге немного, а не сотни.
- **Сортировка и пагинация категории**: `PostRepository::findByCategoryPaginated()`
  строит один `SELECT` с `ORDER BY` по колонке, которую определяет `PostSort` (`date` →
  `published_at`, `views` → `views`), и `LIMIT`/`OFFSET`, посчитанными из номера страницы;
  общее количество статей считается отдельным `COUNT(*)`. Навигация пагинации в шаблоне
  рендерится только когда страниц больше одной.
- **Похожие статьи**: `PostRepository::findSimilar()` выбирает статьи, у которых есть
  хотя бы одна общая категория с текущей, считает число совпавших категорий через
  `GROUP BY` + `COUNT`, исключает саму статью и сортирует сначала по числу общих
  категорий, затем по дате публикации — так более тематически близкие статьи оказываются
  выше даже при небольшом числе просмотров.
- **Счётчик просмотров**: инкрементируется отдельным `UPDATE ... SET views = views + 1`
  при каждом открытии страницы статьи (без дедупликации по сессии/IP — намеренное
  упрощение, в ТЗ не оговорено иное).
- **Слаги**: `Slugger` транслитерирует кириллицу в ASCII по явной карте символов (без
  `iconv`, чтобы не зависеть от локали окружения), схлопывает всё, что не буква/цифра,
  в один дефис и обрезает дефисы по краям; для пустого результата — фолбэк `item`.
- **Сидинг**: `App\Database\Seeder` генерирует категории и статьи без сторонних библиотек
  вроде Faker — заголовки собираются из шаблонов и списка технических тем, описание и
  текст — из банка русскоязычных предложений, каждой статье назначается 1-3 случайные
  категории. Одна из семи категорий ("Черновики") намеренно остаётся без статей, чтобы
  сразу было видно, что правило "категории без статей не попадают на главную" работает.
